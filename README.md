# Лабораторная работа 4. Предварительная обработка веб-данных

Два паука Scrapy собирают новости и товары, очищают данные и одновременно экспортируют JSON и CSV.

## Установка и запуск в Windows PowerShell

Python 3.12. Выполняйте команды из папки проекта.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install --upgrade pip
.venv/Scripts/python.exe -m pip install -r requirements.txt
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.browsers"
.venv/Scripts/python.exe -m playwright install chromium

.venv/Scripts/python.exe run_spider.py --spider news --days 7 --max-pages 5 --output outputs/news.json
.venv/Scripts/python.exe run_spider.py --spider ecommerce --category laptops --stores webscraper --output outputs/ecommerce.csv
.venv/Scripts/python.exe analyze_results.py
.venv/Scripts/python.exe -m pytest -q
```

Активация виртуального окружения не требуется. На Linux/macOS используйте `.venv/bin/python`,
а переменную задайте через `export PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers"`.
Для точного повторения установленного окружения вместо `requirements.txt` используйте `requirements-lock.txt`.

## Источники и границы реализации

- `news`: [Hacker News](https://news.ycombinator.com/news), статическая HTML-лента технологических новостей и публикаций.
  Собираются заголовок, ссылка и дата публикации записи в агрегаторе, а не дата исходной статьи.
  Пагинация по ссылке `More`. Интервал 30 секунд соответствует [robots.txt](https://news.ycombinator.com/robots.txt).
  Пять страниц занимают около 2,5 минут с учётом robots.txt.
- `ecommerce`: [учебный каталог Web Scraper](https://webscraper.io/test-sites/e-commerce/ajax/computers/laptops).
  Chromium действительно выполняет JavaScript, нажимает `Next` и читает карточки из изменившегося DOM.
  Извлечение напрямую из `data-items` или API не используется. Это учебный магазин с клиентской пагинацией,
  а не реальные коммерческие предложения. Источник предназначен для упражнений по скрапингу.

## CLI

```powershell
# Фильтр по любому из ключевых слов, без учёта регистра
.venv/Scripts/python.exe run_spider.py --spider news --keywords "AI,Python" --days 7 --max-pages 10 --min-items 0 --output outputs/filtered.json
```

`--days 0` отключает фильтр давности. Ключевые слова ищутся в заголовках подстрокой, логика ИЛИ.
`--max-pages` ограничивает объём обхода (по умолчанию 5 для новостей, 30 для магазина).
`--min-items` по умолчанию равен 100. Фильтры могут уменьшить выборку, поэтому в примере с ключевыми словами
порог отключён явно. Недостаток данных не маскируется искусственными записями.

Независимо от расширения `--output` рядом создаются `.json`, `.csv`, `.log` и `.stats.json`.
Экспорт перезаписывается при повторном запуске с тем же именем, журнал дополняется.
Код завершения 0 означает успешный сбор с выполненным порогом, 1 — ошибку сбора или недостаток записей,
2 — неверные аргументы. Подробности находятся в журнале и статистике.

## Обработка данных

1. `RecordLoader` структурирует поля карточек и записей.
2. `CleaningPipeline`: `ftfy`, удаление HTML, схлопывание пробелов, `strip`, `lower`, числовая цена,
   канонизация URL с сохранением значимых query-параметров и удалением фрагмента.
3. `ValidationPipeline`: обязательные `title` и `url`, HTTP(S)-ссылка, конечная неотрицательная цена товара.
   Отсутствующий или некорректный рейтинг записывается как `null`. Диапазон рейтинга — 0–5.
4. `DuplicationPipeline`: одна запись на канонический URL. Одинаковые названия товаров с разными URL сохраняются:
   это могут быть разные конфигурации. Нечёткая и семантическая дедупликация не заявляются.
5. `analyze_results.py`: проверка совпадения JSON/CSV, пропусков, дублей и нормализации.
   Для цен вычисляются медиана, квартили и кандидаты в выбросы по правилу 1,5 IQR.

Новостной список не содержит аннотаций, поэтому `summary` — пустая строка.
Цены не заменяются средним или медианой: такая замена создавала бы несуществующие предложения.
Статистические выбросы только отмечаются в отчёте, поскольку высокая цена сама по себе не доказывает ошибку.
Текст приводится к нижнему регистру по требованию лабораторной, URL сохраняют регистр пути.

## Ошибки и тесты

Scrapy повторяет HTTP 429/500/502/503/504 и сетевые таймауты до трёх раз после исходного запроса.
Таймаут Playwright также включён в повтор. После исчерпания попыток вызывается `errback`.
Контекст и страницы браузера закрывает scrapy-playwright, поскольку `playwright_include_page` не используется.
Ожидание новой страницы привязано к изменению ссылки первой карточки, а не к произвольной задержке загрузки.

Тесты не обращаются к публичным сайтам: проверяют очистку, валидацию, дедупликацию, фильтрацию,
парсинг DOM и ошибки CLI. Интеграционный тест поднимает локальный HTTP-сервер: 429 → 503 → 200
и постоянный 503. Он проверяет число настоящих запросов и прекращение повторов.
Фактический сбор с внешних сайтов и результаты проверок описаны в `REPORT.md`.

## Файлы

- `run_spider.py` — интерфейс запуска и критерий успеха.
- `web_spider/` — настройки, ItemLoader, pipelines, два паука.
- `tests/` — автоматические проверки.
- `analyze_results.py` — независимая проверка выгрузок.
- `outputs/` — данные, журналы, статистика и отчёт качества.
- `REPORT.md` — отчёт по выполненной работе.
