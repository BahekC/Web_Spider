# Отчёт по лабораторной работе 4

**Тема:** предварительная обработка и первичный анализ веб-данных.  

## Цель и реализация

Создан Scrapy-проект с двумя пауками: `NewsSpider` для статической новостной ленты Hacker News
и `EcommerceSpider` для учебного каталога Web Scraper с JavaScript-пагинацией.
Данные проходят структуризацию через ItemLoader, очистку, валидацию и дедупликацию.
Каждый запуск одновременно сохраняет JSON и CSV, журнал и машинную статистику.

| Требование | Реализация | Подтверждение |
|---|---|---|
| Два паука | `web_spider/spiders/news.py`, `ecommerce.py` | Два успешных запуска |
| Статический источник | HTML Hacker News, переход по More | 5 страниц |
| Динамический источник | Scrapy-Playwright, Chromium, нажатия Next, ожидание изменения DOM | 20 страниц |
| Не меньше 100 записей у каждого | 149 новостей, 117 товаров | JSON, CSV и `*.stats.json` |
| Очистка | ftfy, удаление HTML, нормализация пробелов, strip, lower | Тесты и независимая проверка выгрузок |
| Дубликаты | Канонический URL | В новостной выборке удалён 1 повтор |
| Валидация | Заголовок, HTTP(S)-ссылка, цена товара | Обязательные поля заполнены |
| Retry и журнал | До 3 повторов, в том числе HTTP 429/503 | Локальный HTTP-интеграционный тест |
| CLI | `--spider`, `--keywords`, `--output` и дополнительные фильтры | Тесты аргументов и реальные запуски |
| JSON и CSV | Два экспорта за один сбор | Поля и число строк совпадают |

## Методика

Для новостей использована публичная лента технологического агрегатора, которую сервер отдаёт в готовом HTML.
Дата записи соответствует публикации в Hacker News. Использован фильтр за последние 7 дней без ключевых слов,
чтобы не ограничивать выборку узкой темой. Интервал запросов — 30 секунд по robots.txt.

В магазине выбран раздел ноутбуков. Браузер загрузил страницу и выполнил JavaScript, после чего паук читал
отрисованные карточки и последовательно нажимал Next. Переход подтверждался изменением ссылки первой карточки.
Скрытые исходные JSON-данные страницы не использовались как замена браузерному сбору.
Полное название извлекалось из атрибута `title`, поскольку видимый текст ссылки сокращён.
Рейтинг извлекался из `data-rating`, а при отсутствии атрибута — по числу звёзд в карточке.

CleaningPipeline исправляет текст через ftfy, удаляет HTML и лишние пробелы, приводит текстовые поля к нижнему
регистру. Цены преобразуются в числа с сохранением дробной части. Валидация выполняется до дедупликации,
чтобы некорректная запись не мешала последующей корректной записи с тем же URL.

Для дедупликации используется URL, а не название: одинаковое название ноутбука может относиться к разным
конфигурациям. Нечёткое и семантическое сравнение не выполнялось.

Точные время начала, длительность, число запросов и статистика браузера сохранены в
`outputs/news.stats.json` и `outputs/ecommerce.stats.json`.
Временные метки записаны в UTC. Журналы `.log` содержат также первоначальные отладочные запуски;
файлы `.stats.json` описывают последний запуск.

Аннотаций в новостном списке нет: `summary` пуст у всех 149 записей. Это известная особенность источника,
а не ошибка обязательного поля. Тексты статей не загружались и аннотации не генерировались.
Некорректные цены не заполняются медианой: это изменило бы смысл предложения.

По критерию 1,5 IQR выбросов не обнаружено. Отрицательная нижняя статистическая граница допустима
для этого расчёта; предметная валидация отдельно запрещает отрицательные цены.
Квартили вычислены с линейной интерполяцией. Цены относятся к учебным данным магазина и не являются
оценкой текущего рынка. Статистический выброс сам по себе не служит основанием удалять товар.

## Тестирование

**31 автоматический тест пройден.** Результат сохранён в `outputs/tests.xml`.

- Очистка HTML, пробелов, регистра, неразрывных пробелов и испорченной кодировки.
- Преобразование цен с точкой, запятой и разделителями тысяч.
- Отклонение пустых обязательных полей, неправильных URL, отрицательных и неконечных цен.
- Дедупликация канонических URL с сохранением различных товаров с одинаковым названием.
- Фильтрация новостей по ключевым словам и дате, пагинация, обработка отсутствующих селекторов.
- Извлечение полного названия и рейтинга товара, отсутствие двойного извлечения вложенной карточки.
- Отказ CLI при некорректных параметрах и неподдерживаемом магазине.
- Независимый контроль экспортов: тест намеренно повреждает данные и проверяет обнаружение ошибок.
- Реальный HTTP-тест на локальном сервере: для последовательности 429, 503, 200 выполнено 3 запроса;
  для постоянного 503 — 4 запроса с прекращением после 3 повторов. Всего 5 повторных запросов.

Проверка `pip check` не обнаружила несовместимых заявленных зависимостей.
Фактические запуски также проверили интеграцию Scrapy-Playwright на Windows.
При подготовке устранена несовместимость новой Twisted со Scrapy 2.13.3; совместимые версии закреплены
в `requirements.txt`, полное окружение — в `requirements-lock.txt`.

Независимый анализ сохранённых JSON/CSV выполняется командой:

```powershell
.venv/Scripts/python.exe analyze_results.py
```

## Воспроизведение и ограничения

Команды установки и повторного запуска приведены в `README.md`.
Новостная лента меняется, поэтому при повторении число записей может отличаться.
Для фильтра по редким ключевым словам порог 100 может не выполняться; CLI возвращает ненулевой код,
а не дополняет результат искусственными записями. По умолчанию успешный запуск требует минимум 100 записей.

## Вывод

Обязательные требования задания выполнены: создана и проверена система с двумя пауками,
получено больше 100 уникальных записей от каждого источника, настроены обработка данных,
повторы запросов и экспорт. Проверка качества не выявила расхождений JSON/CSV, итоговых дублей
или пропусков обязательных полей.
